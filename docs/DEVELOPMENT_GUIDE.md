# v0.96 开发指南

## 新代码放置位置

按最小化原则，将代码放入职责匹配的现有层中：

| 变更类型 | 放置位置 |
|---------|----------|
| 新增本地时序评分 | `fall_detection/features/` |
| 新增相机、深度、姿态或几何能力 | `fall_detection/perception/` |
| 新增 FALL/NO_FALL 业务规则 | `fall_detection/domain/` |
| 新增 AI、MQTT、ROS、HTTP 或通知适配器 | `fall_detection/integrations/` |
| 新增日志、指标、缓存或操作系统服务 | `fall_detection/infrastructure/` |
| 标定、转换、回放或一次性工具 | `fall_detection/tools/` |
| 测试代码 | `tests/` |
| 模型、图片和标定文件 | `assets/` |

**注意**：不要为单个辅助工具创建新的顶层目录。仅当某个功能模块具备独立的职责、生命周期或依赖关系时，才创建新的包。

---

## 添加新功能

按照以下步骤添加新功能：

1. **定义输入输出数据契约**。
2. 在 `config.yaml` 中添加**可配置阈值**。
3. 在对应的包中**实现计算逻辑**。
4. 在 `fall_detection/app/main.py` 中**实例化并调用**该功能。
5. **显式标记证据为有效或无效**；缺失数据不得被静默转换为值为零的正常分数。
6. 如果新功能改变了最终状态判定规则，**更新决策层**（`domain/`）。
7. 添加**正常输入、无效输入、数据缺失和重置**的测试用例。
8. 发布变更时**更新 `V0.96_CHANGELOG.txt`**。

---

## 添加集成适配器

适配器应暴露一个窄接口方法或事件处理器。它**不应直接修改** `FallDetector`、按人存储的历史记录或融合记忆。从应用层注册适配器，并确保其故障对本地检测逻辑**非致命**。

---

## 配置规则

- 运行参数放在 `config.yaml` 中。
- 相对路径从项目根目录或配置目录解析。
- **密钥**（如 `ARK_API_KEY`）放在环境变量中，不要放入配置文件。
- 启动时**校验新配置参数的范围**。
- **不要依赖当前工作目录**来定位资源文件（使用相对于项目根目录的路径）。

## 测试与发布检查清单

在 v0.96 根目录下运行：

```bash
python main.py --self-test --config config.yaml
python -m unittest discover -s tests -v
python -m compileall -q .
```

然后进行**真实相机检查**，验证以下功能：
- RGB 图像采集
- 对齐后的深度图
- 模型加载
- 地面标定
- 追踪 ID 分配
- HTTP 输出
- 程序关闭行为

## 版本管理

保持以下版本号一致：

| 位置 | 示例 |
|------|------|
| `VERSION` | 发布标签，如 `v0.96` |
| `pyproject.toml` | 包版本，如 `0.96.0` |
| `fall_detection/__init__.py` | 运行时 `__version__`，如 `"0.96.0"` |
| `V0.96_CHANGELOG.txt` | 纯文本发布说明 |

**版本号规则：**

- `v0.96.x`：兼容的 Bug 修复
- `v0.97`：新增向后兼容的功能
- `v1.0`：不兼容的架构、配置或 API 变更

## 资源放置位置

| 资源类型 | 放置路径 |
|---------|----------|
| 模型文件 | `assets/models/` |
| 地面标定文件（`ground.yaml`） | `assets/calibration/` |
| 回放测试图片 | `assets/images/` |
| 日志文件 | `Log/`（自动生成，不入库） |
| AI 调试图片 | `debug_ai/`（自动生成，不入库） |

**重要**：Python 包本身应保持可移植性，当这些本地资源单独提供时，代码应能正常运行（即通过 `config.yaml` 配置路径，而非硬编码）。
