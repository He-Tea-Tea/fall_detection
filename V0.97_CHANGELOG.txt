v0.97 CHANGELOG

适用项目：RGB-D Fall Detection

本版本围绕 Ubuntu 22.04 工控机部署、项目依赖隔离、ONNX运行准备、目录职责和维护流程进行整理。P/H/V/S/C 五维评分、地面质量保护、AI复核、HTTP通讯和音频告警的业务公式保持 v0.96 行为。

2. 明确本地依赖目录策略

(1) 使用系统 /usr/bin/python3，不创建 virtualenv、venv 或 Conda 环境。
(2) 通过 fall_local_python.py 在进程内优先加载 python_packages/vN。
(3) 每个依赖版本使用独立目录，避免升级 fall 项目时影响 ROS、相机标定和其他项目。
(4) 使用 install_fall_local.sh 创建新版本目录，已存在的目录拒绝覆盖，避免新旧包混装。
(5) 保留 deploy/install-vN.json 记录安装过程和解析结果。
(6) 使用 deploy/requirements.fall-vN.lock.txt 固定已经验收的完整版本。
(7) 保留 build_tools.* 作为安装阶段临时目录，安装结束后可以清理。
(8) 当前 v1/v2 目录编号只表示依赖快照，不代表代码版本号。

3. 增加 Ubuntu 22.04 部署流程

(1) 启动前检查 Python 版本、Ubuntu版本和 x86_64 架构。
(2) 使用本地 launcher 运行 --check、pip check、main.py --self-test 和真实相机流程。
(3) 明确 Python 搜索路径必须指向项目自己的 python_packages/vN。
(4) 明确本地Python隔离只能隔离Python包，不能替代相机udev规则、系统动态库、ROS环境和设备权限配置。
(5) 增加 runtime_local/ultralytics 和 runtime_local/matplotlib 的写入目录处理建议。

4. 增加 ONNX 部署检查

(1) 明确 .onnx 模型需要 onnxruntime CPU运行库。
(2) 当前实机日志显示：配置已使用 .onnx，但依赖目录中缺少 onnxruntime，程序在模型创建阶段退出。
(3) 后续应在 requirements.fall-local.txt 增加固定版本，例如：
    onnxruntime==1.23.2
(4) 增加ONNX依赖后应新建 python_packages/v2，不要直接改写已经通过检查的 v1。
(5) 创建 v2 后必须重新执行导入检查、pip check、项目自测试和真实相机验收。
(6) ONNX模型是否支持当前IR版本和算子，需要通过真实加载验证，不能只根据安装成功判断。
(7) 如果最终使用 ONNX，应将 fall_local_python.py 的 DEFAULT_DIRECTORY 切换到通过验收的依赖目录。

2. 不修改本地 FALL/NO_FALL 状态机的确认和恢复条件。
3. 不修改 2D/3D 姿态冲突保护逻辑。
4. 不修改地面质量不足时对绝对高度判断的保护。
5. 不修改深度髋高跳变保护和历史更新规则。

   {"fall": false}
9. 不修改 /reset 的全部人员和指定 person_id 重置接口。
10. 不修改 ground_detector.py 的初始地面标定算法。
11. 不修改 FALL 和恢复音频的触发时机。

五、升级到 v0.97 的建议顺序

1. 保留当前 python_packages/v1 作为回退版本。
2. 在 requirements.fall-local.txt 增加 onnxruntime 固定版本。
3. 执行 bash install_fall_local.sh v2。
4. 执行 /usr/bin/python3 -I -S fall_local_python.py --deps v2 --check。
5. 执行 /usr/bin/python3 -I -S fall_local_python.py --deps v2 -m pip check。
6. 执行 /usr/bin/python3 -I -S fall_local_python.py --deps v2 main.py --self-test。
7. 执行 /usr/bin/python3 -I -S fall_local_python.py --deps v2 main.py。
8. 记录真实相机推理、FPS、内存、CPU占用、AI请求和HTTP发送结果。
9. 通过实机验收后导出 deploy/requirements.fall-v2.lock.txt。
10. 将 fall_local_python.py 的默认依赖目录改成 v2。
11. 连续运行确认稳定后，再考虑删除 v1 和 build_tools.* 临时目录。
12. 如果仍需回退，只需把默认目录改回 v1，或启动时增加 --deps v1。
